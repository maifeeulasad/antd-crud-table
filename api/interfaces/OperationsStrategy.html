    refreshAfterMutation?: boolean

    Re-read the list after a successful mutation.

    Defaults to true for standalone hook consumers, which render from state.data. CrudTable sets it false: it renders from ProTable's own request pipeline and reloads through actionRef, so leaving this on issued two list requests for every write.
